# 微信端演示脚本（面试用）

面向：面试现场用手机微信打开系统，按「录题 → 建卷下发 → 学生作答 → AI 评分 → 教师复核 → 成绩统计 → 相似度报告 → 学情 PPT」完整走一遍。

---

## 一、演示前 10 分钟准备

### 1. 启动环境（笔记本）

| 服务 | 命令 / 说明 |
| --- | --- |
| MySQL | 已装服务，库 `ai_marking`，账号 `root / 20060302` |
| Redis | 可不启动（失败会自动跳过，不影响登录） |
| RabbitMQ | **AI 异步阅卷必需**，需启动，端口 5672 |
| 后端 | `cd d:\ai-marking-system` → `.\mvnw.cmd spring-boot:run`，等 8080 就绪 |
| 前端 | `cd d:\ai-marking-system\frontend` → `npm.cmd run dev`，等 5173 就绪 |

> MinIO 不用启动：存储已内置本地磁盘回退，上传的图片/PDF 会落到 `d:\ai-marking-system\data\uploads`，通过 `/api/files/**` 直接访问。

### 2. 手机与网络

- 手机与笔记本连**同一个 WiFi**。
- 查笔记本局域网 IP（PowerShell）：

```powershell
ipconfig | Select-String -Pattern 'IPv4'
```

- 手机微信打开：`http://<局域网IP>:5173/m/login`
- 建议提前把该地址生成二维码贴在简历/PPT 上，面试官可自己扫码体验。

### 3. 账号

| 角色 | 账号 | 密码 | 用途 |
| --- | --- | --- | --- |
| 教师（管理员） | `admin` | `123456` | 演示建卷、下发、AI 评分、统计、PPT |
| 学生 | `demo_student` | `123456` | 演示微信作答、查看逐题评分 |

### 4. 大模型 Key（只演示一次即可）

- 教师账号进入「我的 → 全部功能 → 大模型设置」或直接访问 `/m/llm/setting`，填入可用的 Key 并保存（运行时内存保存，重启后端需重填）。
- 提前点一次「测试连通」，避免现场才发现 Key 失效。

### 5. 数据兜底（强烈建议）

提前用 `admin` 跑完一遍完整流程，留下一条**已出分**的答卷。若现场 AI 不返回（网络/额度问题），直接切到这条历史数据进行「教师复核 → 统计 → 相似报告 → PPT」的演示，链路不断。

## 二、微信打开与文件上传说明

1. 微信内打开链接后，若顶部提示「在浏览器打开」，点右上角「…」→「在浏览器打开」，体验更完整（文件选择器会同时出现「照片」和「文件」两个入口）。
2. 新增试卷时的上传按钮已拆成两个：
   - **拍照 / 相册**：`accept="image/*"`，调起相机或相册；
   - **选择 PDF 文件**：`accept="application/pdf,.pdf"`，调起微信文件选择器。
3. 微信内置浏览器若仍只弹「拍摄 / 从相册选择」，属微信自身限制，切到系统浏览器即可选 PDF。

## 三、主线演示脚本（约 6~8 分钟）

> 讲解节奏建议：每步「我做了什么」+「背后用了什么技术」，不要逐页念功能。

### 第 1 步 微信登录（30 秒）

- 操作：微信打开 `http://<IP>:5173/m/login`，用 `admin / 123456` 登录。
- 话术：「整套系统是 Vue3 + Vite 的响应式 H5，同一套路由按设备自动切到移动端 `/m` 路由树，微信里直接可用，无需装 App。」
- 亮点：登录态 JWT + Pinia 持久化；权限由后端下发菜单与按钮权限，前端按 `permission` 控制路由。

### 第 2 步 录入题目（1 分钟）

- 操作：「全部功能 → 主观题目」→ 新增：题干、参考答案、评分规则、满分。
- 话术：「主观题的关键不是录题，而是把**评分规则**结构化，AI 阅卷时按规则逐点给分，避免大模型自由发挥。」
- 亮点：评分规则字段直接进入 Prompt 模板，支持按题型配置不同 Prompt。

### 第 3 步 建卷并下发（1 分钟）

- 操作：「试卷管理 → 新增」：编号、标题、课程、作答模式选**线上作答**、设置开考/收卷时间；可选上传 PDF 或拍照解析题目 → 保存 → 「发布」→「下发」选择班级或指定学生。
- 话术：「试卷状态是单向流转：草稿 → 待考试 → 阅卷中 → 已归档，防止误操作；下发按班级或按人，学生端只看到发给自己的卷。」
- 亮点：上传走本地存储回退，不依赖对象存储；PDF/图片解析自动抽取题目和题干。

### 第 4 步 学生微信作答（1 分钟，建议第二台手机或退出重登）

- 操作：`demo_student / 123456` 登录 → 底部「学习 → 我的试卷」→「去作答」→ 逐题填写 → 提交。
- 话术：「学生提交的是结构化 JSON，后端会统一规范成 `questionId + 题号 + 答案` 的数组，保证后续 AI 和教师看到的是同一份数据。」
- 亮点：移动端专为学生做了大按钮、逐题卡片、进度提示；提交后立即生成答卷记录。

### 第 5 步 AI 评分（1 分钟）

- 操作：切回 `admin` →「阅卷 → 任务监控」查看异步阅卷进度 → 进入答卷详情查看逐题 AI 分与评语。
- 话术：「AI 阅卷是**异步**的：提交后投递到 RabbitMQ，消费端按题调用大模型，逐题结果落 `exam_answer_item` 表，前端轮询任务状态。这样即使大模型慢也不会阻塞提交，还能失败重试。」
- 亮点：异步 MQ 解耦、逐题并发、Prompt 按评分规则生成、AI 只给参考分。

### 第 6 步 教师复核改分（1 分钟）

- 操作：答卷详情里逐题核对「考生作答 / AI 参考分 / 最终得分」→ 改分并填评语 → 保存 → 「成绩复核」页面确认发布。
- 话术：「AI 给参考分，最终分由教师确认，这是教育场景的合规底线。系统把每一步都留在逐题明细里，可追溯。」
- 亮点：AI 分与最终分双字段；逐题评语；复核状态机。

## 四、三个简历亮点专题演示

### 亮点 1 · 成绩统计（`/m/grade/statistics`）

- 操作：进入「成绩统计」，展示平均分、最高/最低分、及格率、分数段分布、班级对比。
- 话术：「统计不是简单平均值，而是按班级、按题、按知识点三个维度聚合，数据直接来自逐题明细，所以能定位到‘哪道题全班都错’。图表用 ECharts 在移动端自适应。」
- 可加一句：「同页可导出成绩表给教务。」

### 亮点 2 · 指纹相似度报告（`/m/plagiarism/compare`、`/m/plagiarism/report`）

- 操作：选一份试卷 → 运行相似度比对 → 打开抄袭报告，展示相似对、相似度百分比、命中片段。
- 话术：「我们把每份答卷做了**文本指纹**（分片 + 哈希 + 相似度计算），两两比对找出高相似答卷对，生成可下发的报告。这是老师人工几乎做不到的事——一个班 50 份卷子就是 1225 次比对。」
- 亮点：指纹降维 + 两两比对；报告可直接在微信里看，不需要装客户端。

### 亮点 3 · 学情 PPT 一键生成（`/m/learning/ppt`）

- 操作：「学情 → PPT生成下载」→ 选择试卷 → 生成 → 下载/预览。
- 话术：「讲评课最费时间的是做 PPT。系统把成绩分布、错题 Top、知识点得分率、AI 讲评建议自动组织成一份 PPT，老师改几页就能上课。」
- 亮点：统计结果 → 结构化大纲 → PPTX 生成；文件存本地回退目录，手机可直接下载。

## 五、完整演示顺序（推荐口播版）

1. 「这是微信里直接打开的系统，不用装 App。」（登录）
2. 「老师先录一道主观题，重点是结构化评分规则。」（录题）
3. 「建卷、下发到班级。」（建卷下发）
4. 「学生用手机微信作答，提交即生成答卷。」（学生作答）
5. 「AI 异步逐题评分，几十秒出参考分和评语。」（AI 评分）
6. 「老师复核改分，AI 只是助手。」（教师评分）
7. 「成绩统计、相似度报告、学情 PPT，都是老师真正省时间的地方。」（三个亮点）
8. 收尾：「技术栈 Vue3 + Spring Boot + MyBatis-Plus + RabbitMQ + ECharts，移动端与桌面端同一套代码、按设备分流。」

## 六、兜底方案

| 现场问题 | 处理方式 |
| --- | --- |
| 大模型 Key 失效 / 无网络 | 切到提前跑好的已出分答卷，从「教师复核」开始演示 |
| RabbitMQ 未启动 | AI 阅卷不推进；改用历史任务讲解异步架构 |
| 微信选不到 PDF | 右上角「在浏览器打开」，或改用图片上传 |
| 手机连不上后端 | 确认同一 WiFi、Windows 防火墙放行 5173/8080 |
| 上传报错 | 确认 `storage.fallback-to-local=true`，检查 `data/uploads` 目录可写 |
